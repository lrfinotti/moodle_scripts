# Moodle Administration Scripts (`moodle_scripts`)

A collection of Bash scripts for managing, backing up, updating, and performing maintenance on a self-hosted **Moodle** instance running on MariaDB/MySQL.

*Credit:* Most scripts are based on administrative utilities created by Ken Task.

## Script Inventory & Descriptions

### Core Administration Scripts (Root Directory)

* **`moodle_update`**
  Automates minor release updates within the current branch (e.g., pulling point updates and security patches). Runs pre-checks, prompts for automated backup execution, puts Moodle into maintenance mode, updates source code via Git, applies database schema updates, restricts permissions on sensitive files (`.git`, etc.), and purges caches. Handles failure gracefully via a maintenance mode teardown trap.

* **`moodle_major_upgrade`**
  Handles major version upgrades by fetching, tracking, and switching to a new stable Git release branch (e.g., `MOODLE_500_STABLE`). Executes CLI cron and environmental compatibility checks prior to placing the site in maintenance mode, upgrading the database schema, and clearing caches.

* **`moodle_backup`**
  Performs an automated full backup of the Moodle site. Archives the entire core web directory (`tar.gz`) and exports a compressed MariaDB/MySQL database dump using credentials stored in a file. Displays disk space usage and recent backups upon completion.

* **`finderrorlogs`**
  A quick utility to recursively locate all `error_log` files starting from the current directory.

---

### CLI & Database Utilities (`admin/cli/`)

* **`cmysql`**
  Opens an interactive MariaDB client session using database credentials dynamically sourced from file.

* **`get_moodle_files`**
  Queries the Moodle database for files matching a specific file extension (e.g., `.mbz`, `.mp4`, `.pdf`). Saves metadata—including file hash, size, and author ID—sorted by filesize in descending order to a TSV file.
  * **Usage:** `./get_moodle_files [extension] [output_file]` *(Defaults to `mbz` and `mbz_files.txt`)*

* **`delete_moodle_files`**
  Processes a TSV file generated by `get_moodle_files`:
  1. Deletes corresponding database records from the `mdla0_files` table.
  2. Moves physical files out of Moodle's content-addressable storage (`moodledata/filedir/xx/yy/hash`) to a backup location.
  3. Creates collision-safe symbolic links in the backup directory mapping original human-readable filenames to content hashes.
  * **Usage:** `./delete_moodle_files <input_file> [backup_directory]`

* **`my_course_backup`**
  A wrapper around Moodle's native `admin/cli/backup.php` script that simplifies running course backups for one or more course IDs into a specified destination directory.
  * **Usage:** `./my_course_backup [-d|--destination <path>] <course_id_1> [course_id_2 ...]`

* **`runcron`**
  Directly triggers Moodle's maintenance cron job via PHP CLI (`admin/cli/cron.php`).

* **`stay`**
  Sends a continuous ping loop to `127.0.0.1` to keep terminal/SSH sessions active during long administrative operations.

## Configuration & Requirements

* **Execution Context:** Most root administration scripts must be executed directly from the root directory of your Moodle installation so `version.php` and relative paths resolve correctly.
* **Database Credentials:** Database utilities expect a credentials file located at `~/.credentials` folder containing:
  ```bash
  DB_USER="your_db_username"
  DB_PASS="your_db_password"
  DB_NAME="your_moodle_database"
  ```
* **Permissions:** Ensure scripts have executable permissions prior to running:
  ```bash
  chmod +x moodle_* finderrorlogs admin/cli/*
  ```
